### Description

This module contains the logic for setup and operation of the Camera node.
Classes included are CameraNode which handles node setup.

----

### Setup

Upon running the module, the module will attempt to discover all cameras connected to the robot
and create a node for each automatically. The module will then attempt to publish each camera's feed
as a compressed image to each camera's individual topic.

----

### Publisher Setup

The camera module automatically generates a topic name with the following naming scheme: 
```
/camera_{camera_num}/image
```

<Callout type="info" title="Automatic Numbering">
The ```camera_num``` is automatically generated at starts at index 0, so the first camera discovered
will upload its topic as ```/camera_0/image```
</Callout>

The publisher will attempt to upload the image feed every 0.1 seconds (10 hz)

## Public Functions

### getCameras

```python
getCameras() -> list[int]
```

This function returns a list of active camera ID's to the caller. It does this by iterating through
ports 0 to n, with n being the last port found before reaching the ```NON_WOKRING_PORT_THRESHOLD```
(6 at the time of writing) and attempting to open it via ```cv.VideoCapture(dev_port)```. 
If its able to be opened and read, it will append itself to ```working_ports```, release the camera
and move onto the next one, or finish detection.


### CameraNode.destroy_node

```python
destroy_node(self) -> None
```

This function overrides the existing ```Node.destroy_node(self)``` function inherited from the 
```Node``` class. On calling, it checks if the camera node has initialized the ```frameCapture```
and if the camera has been opened via cv. if so, it releases the camera back to ROS and calls the 
original ```destroy_node``` function (```super().destroy_node```)

## Private Methods

<Callout type="warn" title="Accessing Private Methods">
    These methods should only be called within the ```CameraNode``` class.
</Callout>

### CameraNode._publishCameraFrame

```python
_publishCameraFrame(self) -> None
```
This function locks the thread and attempts to call ```frameCapture.read()```. If a frame is 
returned (as signified from the value of ```ret```), it will then generate a topic message by
converting the frame into a compressed jpeg. It will then add the timestamp, and ```frame_id``` 
(the id being equivilant to ```f"camera_{self._camera_id}_optical_frame"```). then publishing the
msg
