title: Camera Module
description: Discover USB cameras, publish compressed streams, and support downstream perception nodes.

### Description

The camera module is the low-level image source for the rover. It discovers connected cameras with
OpenCV, creates a ROS 2 node for each one, and publishes compressed JPEG images on a per-camera
stream.

The implementation lives in `src-platform/camera/camera/camera.py` and exposes the `CameraNode`
class and helper function `getCameras()`.

### Camera discovery

`getCameras()` scans device indices starting at `0` and stops after a short run of ports that fail to
open. For each working camera, it records the index and returns the list of active camera IDs.

This discovery step is intentionally conservative: it checks whether a device can actually be opened
and read before advertising it as usable. That keeps the robot from spinning up empty or broken camera
nodes.

### ROS 2 behavior

Each discovered camera becomes a separate `CameraNode` instance with a node name of the form:

```text
camera_node_{camera}
```

The node publishes a compressed image stream on the topic:

```text
/camera_{camera_num}/image/compressed
```

where `camera_num` is the sequential ROS topic index, beginning at `0` for the first discovered
camera.

<Callout type="info" title="Important behavior">
The OpenCV device index and the ROS topic index are not always the same value. The ROS topic name is
assigned by the order in which cameras are discovered, starting at `0`.
</Callout>

The publisher sends frames at a fixed rate of 10 Hz by creating a timer with a 0.1 second period.

### Setup and launch

Launch the camera node with:

```bash
ros2 run camera camera
```

This process auto-discovers all available cameras and publishes one stream per detected device.
Other nodes, such as the AR tag detection node, can then subscribe to the image topic for the
relevant camera.

## Public functions

### `getCameras()`

```python
getCameras() -> list[int]
```

Returns a list of active camera device indices. It loops through likely device numbers, uses
`cv.VideoCapture(dev_port)` to test each one, and appends only ports that successfully read frames.

### `CameraNode.destroy_node()`

```python
destroy_node(self) -> None
```

This override ensures the hardware stream is released before the base ROS `destroy_node()` method is
called.

## Internal behavior

### `CameraNode._publishCameraFrame()`

```python
_publishCameraFrame(self) -> None
```

This method reads a frame from the camera, converts it to a JPEG with `cv_bridge`, stamps it with the
current ROS time, and publishes the compressed message.

The frame metadata includes the camera optical frame ID:

```text
camera_{self._camera_id}_optical_frame
```

This is the frame name used by downstream consumers when they need to reference the image in ROS TF or
pose calculations.
