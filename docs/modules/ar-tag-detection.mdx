----
### Description

This is a low-level/medium-level module that contains the logic for detecting ArUco fiducial
markers in compressed camera frames and publishing the results as ROS 2 topics. Classes included
are `TagDetectionLogic`, which performs OpenCV-based detection and marker corner processing, and
`ArTagDetectionNode`, which hooks the logic into a ROS node, subscriptions, and publishers.

----

### Setup

When launched, the node will create a subscriber to the configured camera image topic. By default it
subscribes to `/camera_0/image/compressed`, but this can be changed by passing `--camera-id N`
when starting the node:

`ros2 run ar_tag_detection ar_tag_detection -- --camera-id N`

where `N` is the camera index. If no value is provided, it defaults to `0`.

The node publishes detection results to topics under `/camera_{camera_id}/tags`, including the
annotated image, the list of detected IDs, and the corner coordinates for each marker. A valid
camera node must already be publishing compressed images to the ROS graph for detection to work.

<Callout type="error" title="Important Note">
    It is important to note that in order to launch this node, a valid camera node is required to be
    operating and publishing to the ROS.
</Callout>

----

### Publisher Setup

The AR Detection Module automatically generates topic names based on the `camera_id` provided on
initialization.

<Accordions>
    <Accordion title="Tag Detection Topic">
        When a valid ArUco tag is detected, the node publishes the annotated frame with drawn markers
        to `/camera_{camera_id}/tags`.
    </Accordion>
    <Accordion title="Tag ID Topic">
        Each detected marker's ID is published as an `Int32MultiArray` on
        `/camera_{camera_id}/tags/ids`.
    </Accordion>
    <Accordion title="Tag Corners Topic">
        Each detected tag's four corner coordinates are published as flattened `Int32MultiArray`
        data on `/camera_{camera_id}/tags/tag_corners`.
    </Accordion>
</Accordions>

----

### Subscriber Setup

The node subscribes to the compressed image topic associated with the selected camera, for example
`/camera_{camera_id}/image/compressed`. Each new image triggers `ArTagDetectionNode.frame_callback`,
which rate-limits processing using the `process_rate_hz` parameter and then passes the frame to
`TagDetectionLogic.feedFrame`.

----

## Public Functions

### TagDetectionLogic.feedFrame

```python
feedFrame(self, frame: CompressedImage) -> tuple[CompressedImage, Int32MultiArray, Int32MultiArray]
```

This function accepts a compressed camera frame, converts it to a BGR OpenCV image, runs ArUco
marker detection, and returns the annotated frame plus arrays containing detected tag IDs and corner
coordinates. If one or more markers are found, it draws the marker outlines on the image,
flattens the `ids` array, and converts each tag's four corners into a list of `[x, y]` values for
publishing.

### ArTagDetectionNode.frame_callback

```python
frame_callback(self, msg: CompressedImage) -> None
```

This callback is triggered when a new compressed image is received on the configured camera topic. It
enforces the configured `process_rate_hz` throttle, updates the last processed timestamp, calls
`TagDetectionLogic.feedFrame`, and then publishes the resulting image, tag IDs, and tag corner
arrays to their respective topics.

## Private Functions

<Callout type="warn" title="Accessing Private Functions">
    These functions should only be called within the `TagDetectionLogic` class.
</Callout>

### TagDetectionLogic._handleValidTagCorners

```python
_handleValidTagCorners(self, corners: np.ndarray) -> tuple[Point2D, Point2D, Point2D, Point2D]
```

This function reshapes the raw corner data returned by OpenCV into a consistent 4-corner ordering:
top-left, top-right, bottom-right, and bottom-left. Each corner is converted from floating-point
OpenCV coordinates into integer `(x, y)` tuples for downstream publishing and logging.
